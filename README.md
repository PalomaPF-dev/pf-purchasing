# PF購買単価

購入品単価の登録・承認・改訂履歴を管理する社内システム（Palomaシリーズ）。
mcframe（基幹システム）への取込データ出力までを一気通貫でカバーします。

- **担当取引先による制限** — 一般権限は取引先マスタで自分が担当に設定された取引先のみ、申請・閲覧できる（管理者は全件）。担当は取引先ごとに**企画G（バイヤー主担当・副担当）＋管理G（チェイサー）**の3枠
- **ユーザー登録（社員マスタ）** — 社員番号・氏名・承認W/F（MGR/部門長）・権限をユーザーごとに追加・編集。**承認W/Fは保存した時点で承認者に反映**。担当窓口取込の氏名→社員番号の名寄せにも使用（ログインアカウントはポータルの一括発行・SSOで作成）
- **単価申請** — ①取引先の選択と②明細の入力は**同時に進められる**（取引先は保存前に決まっていればよい。選ぶと品目候補・旧単価の自動取得が使える）。品名・単位・現行単価は自動補完。明細は1行入力で、品目CDのとなりに枝番、品名のとなりに単位・ロット数、新単価の枠に（適用日・新単価・支給単価・適用終了日）、続けて旧単価・単価差・**内訳6項目**（支給材建値・材料建値・単価改定・設計変更・為替変動・その他）・月当たり（数量・月額・改訂影響額）。**適用日は前回の適用終了日の翌日**を既定にする（旧単価の取消日＝前回の適用終了日）。**改訂理由は申請タイトル**に入れる（明細の備考は補足用）
- **単価改訂の影響額** — 明細に月当たり数量を入れると、月額（新単価×数量）と改訂影響額（単価差×数量）を自動計算。合計と年換算を申請画面・詳細・承認用紙に表示
- **承認ワークフロー** — 申請 → MGR承認 → 部門長承認。申請者に**承認バイヤー**を設定すると、MGR承認の前に**バイヤー確認**が入る（バイヤー同士の双方チェック用・任意）。段階ごとの**一括承認・一括差し戻し**、差し戻し・コメントスレッド対応
- **申請の修正・取り消し・削除** — 提出後は申請者本人／管理者が**取り下げて下書きに戻し**て修正。下書き（差し戻し含む）は本人／管理者が**一覧・詳細から削除**できる（提出済みは取り下げてから）。承認済みも管理者が**承認取消**でき、単価履歴の反映（直前単価の適用終了日を含む）を元に戻す。MC出力済みは確認のうえでのみ取消可
- **承認W/Fの指定** — MGR・部門長は**ユーザー登録の「承認W/F」でユーザーごとに指定**（保存した時点で承認者に反映）。MGRが複数いる場合は**申請者ごとに承認担当者を割当**でき、割り当てた申請はその担当者だけが承認・差し戻しできる（承認画面も担当分のみ表示）。段階名称も同じ画面で変更でき、専用の設定画面は持たない
- **申請番号** — 提出時に採番。書式（`{YYYY}{MM}-{SEQ4}` など）と連番のリセット単位（年／月／なし）を画面から設定。ルール変更後は**既存の申請番号の振り直し**（変更内容の事前確認つき）で過去分もそろえられる
- **単価申請書（PDF）** — 現行の紙帳票「登録品単価連絡書」の様式。A4横1枚に収まる固定割付（22列・申請画面と同じ項目と並び）。品番・品名・**単位・ロット数**・納入場所に続けて、新単価（適用日・支給単価・単価・買入単価）と旧単価（取消日・単価・買入単価）を左右に対比し、単価差の内訳6項目、月当たり（数量・**月額**・改訂影響額）、備考。改訂理由は上部に表示（申請タイトル）。承認欄（部門長・MGR・担当）つきでブラウザ印刷からPDF出力
- **見積書AI取込** — 見積書（Excel/PDF/画像）を Claude が読み取り、プレビューで確認・修正してから申請明細へ反映（複数ファイル一括・PF品質管理/PF設備管理と同仕様）
- **添付資料** — 申請に見積書・仕様書などを添付（1ファイル4MB・複数可）。申請詳細だけでなく、承認後は**単価履歴の各行からも閲覧**できる
- **設定メニュー** — 取引先マスタ／品番マスタ／納入場所マスタ／ユーザー登録／初期データ移行を「設定」にまとめて管理（すべて管理者権限）
- **納入場所マスタ** — 納入場所CD・納入場所名・備考・更新ユーザー・更新日時を管理（追加・編集・削除・一括登録／管理者のみ）。mcframe の**場所マスタ**（場所ＣＤ→納入場所CD、場所名→納入場所名、更新ユーザ名・更新日時）をそのまま取込でき、**論理削除された場所は「無効」として登録**（履歴の名称表示には使う）。単価履歴などの画面でCDのとなりに名称を表示。移行データ・単価改訂履歴の取込時にも自動登録（全角CDは半角に正規化）
- **品番マスタ** — 品目CD・品名・**単位**・科目・科目名・科目内訳・借方ICS科目名（製造）・品目区分・材料区分を管理。追加・編集・削除に加え、7万行規模の一括登録に対応（CSVはブラウザで分割送信するためサイズ制限なし。同一品目CDは品目区分を「3/7」形式でまとめる）。**現在の取引先**と**適用日**は単価履歴の最新適用単価から自動表示（取引先名は取引先マスタから連携）
- **一括登録** — Excel/CSV の一括取込は各マスタ画面に内蔵（テンプレートDL付き。担当窓口・品目マスタは既存Excelをシート名で自動判別して取込可）。単価申請の一括取込は**旧単価の入力が不要**で、取込時に単価履歴（適用日の前日時点で有効な単価）から自動補完し、品名・単位・ロット数も履歴から補う
- **MC取込CSV出力** — 部門長承認済みの単価を mcframe の購買単価取込フォーマット（52列・1行目=項目キー/2行目=日本語ラベル）で出力。**更新は適用日・単価・改訂前単価のみで、他の項目は現行の登録値を維持**。申請詳細からの単票出力・出力済み管理つき
- **単価履歴** — 一覧は**最新の適用日が先頭**（下に行くほど古い）。品目の詳細は品目×取引先×納入場所×**ロット**ごとに時系列表示（ロット違いの単価を混ぜない）。品名・取引先名・納入場所名は**各マスタから連携表示**し（履歴に記録された名称があればそちらを優先）、マスタの名称でも検索できる。検索ボックスは入力に応じて**候補（品番・取引先・納入場所）を表示**し、選ぶとそのCDで検索する（↑↓・Enterで選択可）。**項目別の絞り込み**（品目CD／品名／取引先／納入場所／備考・複数指定はAND）、**適用期間の範囲指定**（「この期間に改訂」／「この期間に適用されていた」を選択）、**単価差の要因での抽出**（支給材建値・材料建値・単価改定・設計変更・為替変動・その他）と、**見出しクリックでの並び替え**（品目CD・品名・取引先・納入場所・単価・適用開始・適用終了・備考・区分／昇順降順）に対応。**備考（改訂理由）は一覧にも列として表示**。一覧・品目の詳細とも、**単価の右に改訂前・差額を置き、差額の右に要因ごとの内訳6列**（支給材建値・材料建値・単価改定・設計変更・為替変動・その他）を並べて、どの要因でいくら動いたかをそのまま読み取れる（値上げは赤・値下げは緑、金額のない要因は「—」）。申請No・申請者・添付資料も記録として保持
- **データ移行** — mcframe からエクスポートした単価情報（21万行規模）をブラウザから分割送信で取込（冪等・再実行可）。**同じ品目・取引先・納入場所・適用開始日でもロット数が違えば別の単価**として取り込む（ロット違いの単価が落ちない）。**単価改訂履歴（理由つき）**を後から反映して、移行済み履歴に改訂理由・内訳・担当者を補完し、名称が空のままの品番・取引先・納入場所マスタにも名称を書き戻す。照合は品目CD・取引先CD・開始日を必須に、**納入場所CD・ロットの一致する履歴を優先**（ロット違いの単価に別の理由が付かない）

## 技術構成

- Next.js (App Router) + Tailwind CSS 4 — 他のPalomaシリーズと同一パターン
- Neon Postgres（`DATABASE_URL`）/ next-auth（社員番号ログイン・JWT）
- `@paloma-pf/ui` 共通シェル / ポータルSSO・一括アカウント発行（`PF_PROVISION_KEY`）
- Anthropic API（見積書AI読み取り）/ exceljs（Excel取込）

## 本番環境

- URL: https://purchasing.paloma-pf.com （ポータル https://portal.paloma-pf.com からSSOで起動）
- ポータル側の登録: pf-portal（アプリキー `purchasing`）

## 開発

```bash
npm install
npm run dev   # http://localhost:5183
```

### 環境変数（.env.local）

| 変数 | 用途 |
| --- | --- |
| `DATABASE_URL` | Neon Postgres（購買単価専用DB） |
| `NEXTAUTH_SECRET` / `NEXTAUTH_URL` | next-auth（本番は `https://purchasing.paloma-pf.com`） |
| `PF_ADMIN_BOOTSTRAP_HASH` | 統一管理者（login_id=admin）の bcrypt ハッシュ（任意） |
| `PF_PROVISION_KEY` | ポータルSSO・一括アカウント発行の共有キー（ポータルと同一値を設定） |
| `ANTHROPIC_API_KEY` | 見積書AI取込（未設定時は該当機能のみ無効） |

DBスキーマはアプリ起動時に冪等に自動作成されます（マイグレーション不要）。

## 初期セットアップの流れ

1. 環境変数を設定してデプロイ（Vercel）または `npm run dev`
2. `/register` で最初の管理者を作成（`PF_ADMIN_BOOTSTRAP_HASH` を設定した場合は `admin` でログイン可）
3. **設定 → ユーザー登録**（`/employees`）で社員を登録し、承認者は各社員の「承認W/F」で MGR／部門長 を指定（ログインアカウントはポータルの一括アカウント発行・SSOで作成されます）
4. **設定 → 取引先マスタ / 品番マスタ**の各画面から一括登録。取引先マスタでは続けて「取引先の担当窓口」を取込むと企画G（バイヤー）・管理G（チェイサー）が割り当たります
5. **設定 → 初期データ移行**（`/migrate`）: mcframe の単価情報エクスポート（Excel）を「CSV UTF-8」で保存し、そのままアップロード
   - 論理削除行（del_flg≠0）は自動スキップ。再実行しても二重登録されません
   - 移行後「マスタから名称を補完する」を実行すると履歴に品名・取引先名が入ります
   - 続けて「単価改訂履歴の理由を単価履歴に反映する」を実行すると、備考（改訂理由）・単価差の内訳・担当者名が履歴に入ります
6. 以後は「単価申請 → 承認 → MC取込出力」の運用サイクル

## MC取込CSVの仕様

`MC取込フォーマット.xlsx` と同一の列構成で出力します。

- 1行目: 項目キー（`del_flg, wg_cd, … itm_p.itm_cd, … upri1_p.upri, …`）
- 2行目: 日本語ラベル（論理削除、ワーキンググループＣＤ、…）
- 3行目以降: データ（適用開始日/終了日は `YYYYMMDD`、単価=`upri1_p.upri`、改訂前単価=`upri2_p.upri`）
- 文字コード: UTF-8（BOM付き・Excel対応）。Shift_JIS が必要な場合は Excel 等で変換してください
